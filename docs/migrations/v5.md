# v5: Unified Async Model (`Result` + `ResultTask`)

v5 unifies Resultar around one synchronous type (`Result<T, E>`) and one lazy asynchronous workflow type (`ResultTask<T, E, R>`), making `task.runResult()` return a native `Promise<Result<T, E | ScopeError<R>>>`.

Eager `ResultAsync` and `StrictResultAsync` are removed from the root `"resultar"` entry point and moved to a **`@deprecated` `"resultar/async"` compatibility subpath** that preserves the v4 eager surface (including `fromTask`, `retry`, `withResource`, `fromCallback`, `tap`, `tapError`, `safeTry`, and `DisposableResultAsync`) throughout v5.x for gradual migration.

## Core v5 mental model

| Use case                                                        | Type                                                 | Entry point                           |
| --------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------- |
| Pure synchronous validation, parsing, domain logic              | `Result<T, E>` (`StrictResult<T, E>`)                | `"resultar"` (or `"resultar/result"`) |
| Any async I/O, retries, timeouts, scopes, services, concurrency | `ResultTask<T, E, R>` (`StrictResultTask<T, E, R>`)  | `"resultar"` (or `"resultar/task"`)   |
| Imperative boundary (`async` handler, script, test)             | `Promise<Result<T, E>>` via `await task.runResult()` | Native `Promise`                      |
| Legacy eager in-flight boundary adapter (opt-in)                | `ResultAsync<T, E>` (`StrictResultAsync<T, E>`)      | `"resultar/async"`                    |

```ts
import { ResultTask, Retry } from "resultar";

const loadUser = (id: string) =>
  ResultTask.tryPromise({
    try: (signal) => fetchUser(id, signal),
    catch: (cause) => new LoadUserError({ id, cause }),
  })
    .retry(Retry.policy({ times: 2, delayMs: 100, backoff: 2 }))
    .timeout(2_000, () => new LoadUserTimeoutError({ id }));

// Execute at the imperative boundary -> native Promise<Result<User, ...>>
const result = await loadUser("u_1").runResult();
const body = result.match({
  ok: (user) => ({ status: 200, user }),
  err: (error) => ({ status: 502, error: error._tag }),
});
```

## Automated migration with `resultar-check migrate-v5`

`resultar-check` ships a type-aware `migrate-v5` subcommand that previews and applies safe mechanical v4 -> v5 edits and lists manual review sites:

```sh
# 1. Read-only preview (modifies nothing)
pnpm exec resultar-check migrate-v5 --project tsconfig.json

# 2. Machine-readable JSON report or single-file preview
pnpm exec resultar-check migrate-v5 --project tsconfig.json --json
pnpm exec resultar-check migrate-v5 --project tsconfig.json --file src/orders.ts

# 3. Apply safe mechanical edits in place
pnpm exec resultar-check migrate-v5 --fix --project tsconfig.json

# 4. Run full type + Resultar diagnostic verification
pnpm exec resultar-check --project tsconfig.json
```

### What `--fix` updates automatically

- Splits root `"resultar"` imports of eager compatibility symbols (`ResultAsync`, `StrictResultAsync`, `DisposableResultAsync`, `okAsync`, `errAsync`, `unitAsync`, `fromPromise`, `fromSafePromise`, `tryResultAsync`, `fromCallback`, `fromThrowableAsync`, `runPromise`, `tryAsync`, `tryCatchAsync`, `safeTry`, and their associated types) into `"resultar/async"`.
- Renames `requestJsonTask`, `requestJsonZodTask`, and `requestJsonTypeBoxTask` (and their `*Task*` input types) to `requestJson`, `requestJsonZod`, and `requestJsonTypeBox` (resolving symbols via TypeScript so shadowed locals are untouched).
- Rewrites `task.toResultAsync()` and `ResultTask.toResultAsync(task)` to `ResultAsync.fromTask(task)` (reusing any aliased `ResultAsync` value binding such as `Eager`).
- Rewrites `task.runResult().unwrapOrThrow()` to `task.runPromise()`, safe post-settlement `.match(...)` / `.unwrapOr(stableValue)` chains to `.then(...)`, and fluent `ResultAsync` chains on `runResult()` to `new ResultAsync(task.runResult())` (using any local `ResultAsync` alias).
- Rewrites `Result.gen(async function* ...)` / `Result.fn(async function* ...)` to `ResultAsync.gen` / `ResultAsync.fn`, `result.asyncMap` / `result.asyncAndThen` to standalone `asyncMap` / `asyncAndThen` from `"resultar/async"`, and `result.safeUnwrap()` to `result`.
- Rewrites removed core v4 aliases to their canonical names:
  - `ResultTask.succeed` / `.fail` -> `ResultTask.ok` / `.err`
  - Task `.mapError` / `.flatMap` / `.catchAll` -> `.mapErr` / `.andThen` / `.orElse`
  - `Result.combine` / `Result.combineWithAllErrors` / `Result.tryCatch` -> `Result.all` / `Result.validateAll` / `Result.try`
  - Legacy `{ ok, error }` / `{ onSuccess, onFailure }` keys on `Result#match` and `ResultTask#match` -> `{ ok, err }`

### What `migrate-v5` flags for manual review

- `task.runResult().unwrapOr(...)` and `task.runResult().match(...)` with non-trivial or mutable fallback/handler bindings (e.g. `let`, parameters, calls) whose evaluation timing could differ inside `.then(...)`.
- Call sites of v4 eager `requestJson` / `requestJsonZod` / `requestJsonTypeBox` (including opaque option variables and spreads) — in v5 these return a lazy `ResultTask` and will not execute until `.runResult()` or `yield*` is added.
- Removed root imports (`tryCatch`, `try`, `ResultTaskRetryOptions`), `TaggedErrorClass.errAsync(...)`, and `Result#tap` / `Result#tapError`.
- Deprecated eager helpers preserved in `"resultar/async"` during v5.x (`safeTry`, `ResultAsync.retry`, `ResultAsync.withResource`, `ResultAsync.fromCallback`, `ResultAsync#tap` / `tapError`, `ResultAsync#toAsyncDisposable`) so teams can schedule incremental migration to `ResultTask`.

## Breaking changes and API mapping

### 1. `runResult()` returns native `Promise<Result<T, E | ScopeError<R>>>`

In v4, `task.runResult()` returned `ResultAsync` (`PromiseLike<Result<...>>`). In v5, `task.runResult()` and `ResultTask.runResult(task)` return a native `Promise<Result<T, E | ScopeError<R>>>`.

- **Before (v4):**
  ```ts
  const label = await loadUser(id)
    .runResult()
    .map((user) => user.name)
    .unwrapOr("anonymous");

  await assert.rejects(Promise.resolve(failingTask.runResult()));
  ```
- **After (v5):**
  ```ts
  const label = (
    await loadUser(id)
      .map((user) => user.name)
      .runResult()
  ).unwrapOr("anonymous");

  // Or fold lazily and execute with runPromise():
  const label2 = await loadUser(id)
    .map((user) => user.name)
    .unwrapOr("anonymous")
    .runPromise();

  // Native Promise — no Promise.resolve(...) wrapper needed:
  await assert.rejects(failingTask.runResult());
  ```

#### Sharing one in-flight execution across callers

Because `task.runResult()` returns a native `Promise`, sharing one in-flight execution at an imperative boundary needs no wrapper class:

```ts
const pending = loadConfig().runResult();
const [first, second] = await Promise.all([pending, pending]);
```

To cache a workflow's result across repeated lazy Task compositions, use `ResultTask.memoize(task)`.

### 2. Root `"resultar"` entry point and `"resultar/async"` subpath

| v4 API                                                                                                                                                                                                                             | v5 Replacement                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `import { ResultAsync, StrictResultAsync, okAsync, errAsync, unitAsync, fromPromise, fromSafePromise, tryResultAsync } from "resultar"`                                                                                            | Prefer `ResultTask` from `"resultar"`, or import eager compat from `"resultar/async"`                                                                                                                                                                                                      |
| `Result.gen(async function* () { ... })` / `Result.fn(async function* ...)`                                                                                                                                                        | `ResultTask.gen(function* () { ... })` / `ResultTask.fn(...)` (or `ResultAsync.gen` / `ResultAsync.fn` from `"resultar/async"`)                                                                                                                                                            |
| `safeTry(function* () { ... })` / `safeTry(async function* () { ... })`                                                                                                                                                            | `Result.gen` (sync), `ResultTask.gen` (lazy async), or `ResultAsync.gen` from `"resultar/async"` (note: modern `gen` returns plain success values, not `ok(value)`)                                                                                                                        |
| `result.asyncMap(fn)` / `Result.asyncMap(fn)`                                                                                                                                                                                      | `ResultTask.fromResult(result).andThen(...)` (or `asyncMap` from `"resultar/async"`)                                                                                                                                                                                                       |
| `result.asyncAndThen(fn)` / `Result.asyncAndThen(fn)`                                                                                                                                                                              | `ResultTask.fromResult(result).andThen(...)` (or `asyncAndThen` from `"resultar/async"`)                                                                                                                                                                                                   |
| `TaggedError.errAsync(props)`                                                                                                                                                                                                      | `TaggedError.taskErr(props)` (or `errAsync(new TaggedError(props))` from `"resultar/async"`)                                                                                                                                                                                               |
| `task.toResultAsync()` / `ResultTask.toResultAsync(task)`                                                                                                                                                                          | `ResultAsync.fromTask(task)` from `"resultar/async"` (to retain an eager contract) or `task.runResult()` / `ResultTask.runResult(task)` (native `Promise<Result>`)                                                                                                                         |
| `ResultTask.succeed` / `ResultTask.fail`                                                                                                                                                                                           | `ResultTask.ok` / `ResultTask.err`                                                                                                                                                                                                                                                         |
| `task.mapError` / `task.flatMap` / `task.catchAll`                                                                                                                                                                                 | `task.mapErr` / `task.andThen` / `task.orElse`                                                                                                                                                                                                                                             |
| `Result.tryCatch` / `tryCatch` / `tryCatchAsync` / `tryAsync`                                                                                                                                                                      | `Result.try` / `tryResult` / `ResultTask.tryPromise` (`tryCatchAsync` / `tryAsync` remain `@deprecated` in `"resultar/async"`)                                                                                                                                                             |
| `result.tap(fn)` / `result.tapError(fn)` (on `Result`)                                                                                                                                                                             | `result.inspect(fn)` / `result.inspectError(fn)` (`ResultAsync#tap` / `tapError` remain `@deprecated` in `"resultar/async"`; `tap` / `tapError` on `ResultTask` compose fallible side effects)                                                                                             |
| `Result.combine` / `Result.combineWithAllErrors`                                                                                                                                                                                   | `Result.all` / `Result.validateAll`                                                                                                                                                                                                                                                        |
| `Result.zip` / `Result.zipWith`                                                                                                                                                                                                    | `Result.all([a, b])` / `ResultTask.zip`                                                                                                                                                                                                                                                    |
| `ResultAsync.{all, combine, combineWithAllErrors, validateAll, zip, retry, retryOrElse, race, raceAll, raceFirst, raceWith, timeout, firstSuccessOf, withResource, loop, iterate, forEach, fromCallback, fromThrowable, fromTask}` | Preserved as `@deprecated` in `"resultar/async"` throughout v5.x; migrate new workflows to `ResultTask` equivalents (`ResultTask.all`, `ResultTask.retry`, `ResultTask.timeout`, `ResultTask.forEach`, `ResultTask.acquireRelease` + `ResultTask.scoped`, `ResultTask.fromCallback`, etc.) |
| `Match` legacy object keys `{ ok, error }` / `{ onSuccess, onFailure }`                                                                                                                                                            | `{ ok, err }` on core `Result` / `ResultTask` (legacy `{ ok, error }` remains supported on `ResultAsync` in `"resultar/async"`)                                                                                                                                                            |
| `Retry` legacy options `{ maxAttempts, ... }`                                                                                                                                                                                      | `Retry.policy({ times, delayMs, backoff, jittered, ... })`                                                                                                                                                                                                                                 |
| `ResultTask.fromResultAsync(existingOrFactory)`                                                                                                                                                                                    | Still supported on `ResultTask` — structurally accepts any `PromiseLike<Result<T, E>>` (including native `Promise<Result<T, E>>` and `ResultAsync` from `"resultar/async"`) without importing `ResultAsync` into core `"resultar"`                                                         |

### 3. `resultar-request`, `resultar-request-zod`, `resultar-request-typebox`

All HTTP helpers now return `ResultTask` directly. The v4 `*Task` duplicate functions and `ResultAsync` re-exports are removed:

| v4 API                                             | v5 Replacement                                                                                          |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `requestJson(...)` (returned `ResultAsync`)        | `requestJson(...)` (returns `ResultTask<T, RequestError>`)                                              |
| `requestJsonTask(...)`                             | `requestJson(...)`                                                                                      |
| `requestJsonZod(...)` (returned `ResultAsync`)     | `requestJsonZod(...)` (returns `ResultTask<T, RequestError>` or mapped domain error via `mapError`)     |
| `requestJsonZodTask(...)`                          | `requestJsonZod(...)`                                                                                   |
| `requestJsonTypeBox(...)` (returned `ResultAsync`) | `requestJsonTypeBox(...)` (returns `ResultTask<T, RequestError>` or mapped domain error via `mapError`) |
| `requestJsonTypeBoxTask(...)`                      | `requestJsonTypeBox(...)`                                                                               |

Because `requestJson*` is now lazy and repeatable, retries, timeouts, and cancellation compose directly:

```ts
import { Retry } from "resultar";
import { requestJsonZod } from "resultar-request-zod";

const fetchUser = (id: string) =>
  requestJsonZod({
    request: (signal) => fetch(`https://api.example.com/users/${id}`, { signal }),
    schema: UserSchema,
  })
    .retry(Retry.policy({ times: 2, delayMs: 100 }))
    .timeout(5_000, () => new RequestTimeoutError({ id }));

const result = await fetchUser("u_1").runResult();
```

### 4. Companion adapters (`resultar-di`, `resultar-hono`, `resultar-fastify`, `resultar-nestjs`)

- All companion adapters have zero runtime or type imports of `ResultAsync`.
- Imperative lifecycle/session boundaries return native `Promise<Result<...>>` or `Promise<Exit<...>>` directly.
- Task-based handlers and DI service factories continue to return `ResultTask<T, E, R>` (and `StrictResultTask<T, E, R>`).

### 5. `resultar-check` v5 diagnostics

- **New rule `no-await-result-task` (default `"error"`):** Flags `await task` where the operand is a `ResultTask` or `StrictResultTask`, preventing the silent bug of awaiting a lazy non-thenable description without running it. Offers a safe `.runResult()` autofix when the task is narrowed, has no unsatisfied service requirements, and the surrounding context expects a `Result` (and guides toward `yield*` inside `ResultTask.gen` / `ResultTask.fn`).
- **Updated `no-promise-resultar` (default `"error"`):** Flags `Promise<ResultTask<...>>`, `Promise<StrictResultTask<...>>`, and mixed Promise unions containing `ResultTask`, while **allowing** `Promise<Result<...>>` and `Promise<StrictResult<...>>` as valid native execution boundaries returned by `task.runResult()`.
- **`prefer-result-async` default changed to `"off"`:** Teams maintaining legacy `"resultar/async"` eager contracts can explicitly opt back in with `"preferResultAsync": "warning"` or `"error"`.
- **`prefer-tap` / `prefer-tap-error`:** Recommend `tap` / `tapError` only on `ResultTask` and `inspect` / `inspectError` on `Result` and `ResultAsync` (suppressing unsafe rewrites when a throwing or rejecting callback could alter the outcome).
