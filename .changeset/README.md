# Changesets

Use this directory to collect release notes and version bump intent before publishing.

Typical flow:

1. Run `pnpm changeset` in a feature branch.
2. Select the packages that should be released and the bump type.
   Active packages, including the request helpers, should be selected explicitly.
3. Commit the generated `.changeset/*.md` file with the code change.
4. Merge to `main`.

The `Release` workflow handles the rest:

- when changesets are present, it opens or updates a `Version packages` PR by running
  `pnpm run version:packages`;
- when that version PR is merged, it runs `pnpm run release:publish`, publishing npm first and JSR
  second.

JSR versions are still sourced from each package's `jsr.json`; `version:packages` keeps those files
in sync with the package versions generated by Changesets.

## Preview releases

Use the permanent `next` branch for npm previews. Enter Changesets prerelease mode with
`pnpm exec changeset pre enter beta` when starting a new beta cycle. Merge the changesets for that
preview into `next`. After validation, the workflow opens or updates a version PR targeting
`next`. Merging the version PR publishes the prerelease packages to npm under the `next` tag.

For example, consumers install `resultar@5.0.0-beta.0` with `pnpm add resultar@next` while that
version is tagged. Each package follows its own version series. The publication checks that every
package has a prerelease version before contacting the registry.

For the stable release, create a branch from the preview, run `pnpm exec changeset pre exit` and
`pnpm run version:packages` there, then merge the stable versions into `main`.
